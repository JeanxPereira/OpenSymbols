# P2: Static Runtime and Generator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `opensymbols generate` turns a user's catalog into an installable package of tree-shakable React components that draw every public symbol in all four rendering modes, at any weight, in two layouts, with knockouts, variable value (color mode), appearance and RTL.

**Architecture:** `@opensymbols/core` is framework-free and browser-safe: the generated data format, weight interpolation, paint resolution and an SVG element model. `@opensymbols/react` turns that model into React elements through `createIcon(data)`. `packages/cli` gains `generate`, which uses `@opensymbols/decode` to read the catalog, encodes each symbol into the format `core` reads, and writes one ESM module per symbol plus index files. An end-to-end test generates from a synthetic catalog and renders the result with `react-dom/server`.

**Tech Stack:** Node ≥ 24.2, pnpm workspaces, TypeScript 5 strict ESM, Vitest, tsup, React 19 (peer), `react-dom/server` in tests.

**Spec:** `Docs/Specs/2026-11-09-opensymbols-design.md` (§2 goals 1–5, §3, §4, §7, §8).

**Plan 2 of 5.** P3 demo, P4 animate, P5 Variable Color timing follow. Out of P2: effects, the Draw clip, Variable Value in `draw` mode (needs the Draw clip, P4), localized drawings, GlyphSize.

## Global Constraints

- TypeScript end to end; no reference to any other project anywhere in the repo.
- No Apple byte in git or npm tarballs; generated packages and test output directories are git-ignored; `pnpm check:pack` stays green.
- `@opensymbols/core` has zero runtime dependencies and no Node APIs (it ships to browsers). `@opensymbols/react` depends only on `@opensymbols/core` and has `react` as a peer (`>=19`).
- Every format fact cites `Docs/format/NN §`; every inference in code is a named constant marked `[INF]` with a one-line reason.
- Approximations are flagged, never silent (spec §4): any output drawn from something not decoded carries `approximate: true` and a reason in `approximations`.
- Errors in `decode` and `cli` are `DecodeError` or a CLI error with a clear message; `core`/`react` never throw on valid generated data and validate `formatVersion`.
- Commits: conventional prefixes (`decode:`, `core:`, `react:`, `cli:`, `docs:`, `build:`), no AI attribution of any kind.
- Weights: `ultralight 1, thin 2, light 3, regular 4, medium 5, semibold 6, bold 7, heavy 8, black 9`; masters are 1, 4, 9 (Docs/format/01 §3.3).
- Hierarchical levels: primary 1.0, secondary 0.5, tertiary 0.18 light / 0.25 dark (Docs/format/05 §3.5).
- Component name rule (spec §7.4): split on `.` (and any other non-alphanumeric character), PascalCase each part, prefix `Sf` when the result starts with a digit; injective over the catalog or `generate` stops naming both.
- Reference build fingerprint (Docs/format/01 §1, §6): CoreUI version 1010, 157,938 renditions, 8,527 public facets.

## Review Focus

1. A symbol whose masters disagree in shape (point-incompatible): `generate` must skip it with its name in the report, never emit a module that interpolates garbage. Test in Task 7.
2. Two icons with knockouts on one page: mask ids must not collide (React `useId`). Test in Task 5.
3. A weight outside 1–9, NaN, or an unknown weight name: clamp or reject predictably, never produce NaN in `d`. Test in Task 2.
4. A palette with fewer colours than roles, or none: last colour repeats; empty palette falls back to the tint. Test in Task 3.
5. A catalog with no `app/`: multicolor still renders with the stand-in palette and the package says `palette: "stand-in"`. Test in Task 8.

**Interfaces:**

  - `interface LayerData { cmd: [start: number, end: number]; role: "primary"|"secondary"|"tertiary"; modes: { monochrome: LayerStyleData; hierarchical: LayerStyleData; multicolor: LayerStyleData; palette: LayerStyleData }; motionGroup: number; variableThreshold?: number; anim?: Record<string, unknown> }` (`anim` carries the remaining `Layer` fields verbatim for P4)
  - `interface VariantData { ops: string /* one char per command, Docs/format/03 §3.2 letters */; argCounts: number[] /* per command */; masters: Partial<Record<1|4|9, { args: number[]; viewBox: [number,number,number,number]; transform: [number,number,number,number,number,number]; metrics: { referencePointSize: number; baselineOffset: number; capHeight: number; leftInset: number; rightInset: number } }>>; layers: LayerData[]; variableValueMode: "color"|"draw"; vcContinuous: boolean; anim?: Record<string, unknown> }`

  - `weightValue(w: Weight): number` (names → 1..9; numbers clamped to [1, 9]; NaN → 4)
  - `interface Interpolated { args: number[]; viewBox: [number,number,number,number]; transform: [number,number,number,number,number,number]; metrics: VariantData["masters"][4]["metrics"]; approximate: boolean }`
  - `interpolate(variant: VariantData, w: Weight): Interpolated`

Weight table `[INF]` (spec §8.2, the decoded table is open): `w ≤ 4 → s_ul = (4 − w)/3, s_b = 0`; `w ≥ 4 → s_ul = 0, s_b = (w − 4)/5`. `p = R + s_ul·(UL − R) + s_b·(B − R)` applied to args, viewBox, transform and metrics alike. `approximate` is false only for w ∈ {1, 4, 9}. A variant with only the regular master (generated with `--masters regular`) returns regular for every weight, `approximate: true` unless w = 4.

### Task 3: `@opensymbols/core`: paint and variable value

**Files:**
- Create: `packages/core/src/paint.ts`
- Test: `packages/core/test/paint.test.ts`

**Interfaces:**
- Consumes: `LayerData`, `PaintData` (Task 2).
- Produces:
  - `type RenderingMode = "monochrome"|"hierarchical"|"multicolor"|"palette"`
  - `interface PaintOptions { mode: RenderingMode; color: string /* tint, CSS */; palette?: string[]; appearance: "light"|"dark"; variableValue?: number; variableValueMode: "color"|"draw"; vcContinuous: boolean }`
  - `interface ResolvedLayer { fill: string; opacity: number; knockout: boolean; visible: boolean }`
  - `resolveLayer(layer: LayerData, opts: PaintOptions): ResolvedLayer`
  - `resolveApproximations(data: SymbolData, opts: PaintOptions): string[]` (adds `"palette"` when `data.palette === "stand-in"` and mode is multicolor; `"variable-value"` when a variable value is applied — see below)

Rules: monochrome → tint; hierarchical → tint at the role level (Global Constraints) multiplied into `opacity`; palette → `palette[roleIndex]` with the last colour repeating, tint when the palette is empty (**Review Focus 4**); multicolor → `named` picks `light`/`dark` by appearance, `fixed` its hex, `tint` the tint, `role` the tint at the role level. `opacity` = style opacity × role level (hierarchical only). `knockout` = `clearBehind`. Variable value in `color` mode (Docs/format/06 §5.1 `variableThreshold`): a layer with a threshold is active when `v >= threshold` (hard cut), or ramps linearly over `threshold ± 0.06` when `vcContinuous` `[INF]`; an inactive layer is drawn at `INACTIVE_ALPHA = 0.25` of its opacity `[INF]` (the dimmed look of inactive layers; the exact factor is not decoded), so `approximations` gains `"variable-value"`. In `draw` mode `variableValue` is ignored in P2 and `approximations` gains `"variable-draw"`.

- [ ] **Step 1: Write the failing tests** for each rule above, with explicit numbers: hierarchical secondary dark → opacity 0.5; tertiary light → 0.18, dark → 0.25; palette `["#111"]` with a tertiary layer → `#111`; palette `[]` → tint; multicolor named dark → its `dark`; threshold 0.5 at v 0.49 → opacity × 0.25, at v 0.5 → full; continuous at v 0.5 → half way between 0.25 and 1 of the layer's opacity (`0.625×`); draw-mode symbol with a variableValue → `approximations` contains `"variable-draw"`.
- [ ] **Step 2:** Run → FAIL. Implement. Run → PASS.
- [ ] **Step 3:** Commit `core: paint resolution and variable value`.

### Task 4: `@opensymbols/core`: the SVG element model and layouts

**Files:**
- Create: `packages/core/src/svg.ts`, `packages/core/src/path.ts`
- Test: `packages/core/test/svg.test.ts`

**Interfaces:**
- Consumes: Tasks 2–3.
- Produces:
  - `serializePath(ops: string, argCounts: number[], args: number[], range: [number, number]): string` (numbers rounded to 3 decimals, `-0` → `0`, single spaces, no exponent notation)
  - `type SvgNode = { tag: "svg"|"g"|"path"|"mask"|"rect"|"defs"|"title"; attrs: Record<string, string|number>; children: SvgNode[] }`
  - `interface RenderOptions extends Omit<PaintOptions, "variableValueMode"|"vcContinuous"> { size: number; weight: Weight; layout: "box"|"text"; direction: "ltr"|"rtl"; idPrefix: string; title?: string }`
  - `buildSvg(data: SymbolData, opts: RenderOptions): { root: SvgNode; approximate: boolean; approximations: string[] }`
  - `pickVariant(data: SymbolData, appearance: "light"|"dark", direction: "ltr"|"rtl"): VariantData` (dark → appearance 1 if present; rtl → direction 5 if the variant set holds both 4 and 5, else the default; Docs/format/05 §4.4)

Structure: `<svg viewBox width height role="img"|aria-hidden="true">` → optional `<title>` → `<defs>` with one `<mask>` per knockout → `<g transform="matrix(a b c d e f)">` → layers in order. A knockout layer is not painted; every layer before it is wrapped in a `<g mask="url(#<idPrefix>-k<i>)">` whose mask is a white rect over the viewBox plus the knockout path in black (Docs/format/06 §5.3, destination-out). Invisible layers are omitted.
Layouts (spec §8.1): `box` → `width = height = size`; viewBox is the square of side `max(w, h)` of the **regular** master's viewBox, centred on it, so a weight change never reflows. `text` → `scale = size / metrics.referencePointSize` `[INF]`; `width = vbW × scale`, `height = vbH × scale`; `style="vertical-align: <baselineOffset × scale>px"` `[INF]`.

- [ ] **Step 1: Write the failing tests:** `serializePath("MLZ",[2,2,0],[1,-0,2.00049,3],[0,3])` → `"M1 0L2 3Z"`; box layout of a 10×5 viewBox at size 24 gives `viewBox "0 -2.5 10 10"`, `width 24`; text layout with referencePointSize 17 at size 34 gives `width = vbW × 2`; a two-layer symbol whose layer 1 is a knockout yields one mask and layer 0 inside a `g` with `mask="url(#p-k1)"` and no painted layer 1; `idPrefix` appears in every mask id; dark appearance picks `a1d0` when present; rtl picks the direction-5 variant only when 4 and 5 both exist.
- [ ] **Step 2:** Run → FAIL. Implement. Run → PASS.
- [ ] **Step 3:** Commit `core: SVG model, layouts and knockout masks`.
