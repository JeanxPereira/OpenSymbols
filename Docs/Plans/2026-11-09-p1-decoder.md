# P1: Foundation and Decoder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A TypeScript monorepo whose `@opensymbols/decode` reads Apple's CoreGlyphs catalog (BOM, `.car`, `BVG `, plists) into a typed `Drawing`, and whose `opensymbols dump` / `opensymbols gate` prove it over every public document.

**Architecture:** `@opensymbols/decode` is pure: every function takes `Uint8Array`s and returns values or throws `DecodeError`; only `packages/cli` touches the disk. Layers go bottom-up (bytes, BOM, CAR, BVG numbers/paths/lists, BVG document, style block, plists, metadata, drawing builder, catalog facade), each with its own tests. Unit tests use hand-built bytes; tests against the real catalog live in `*.catalog.test.ts` and skip when `SF_CATALOG_DIR` is unset.

**Tech Stack:** Node 24, pnpm 10 workspaces, TypeScript 5 strict (`"module": "NodeNext"`, ESM only), Vitest, tsup for builds.

**Spec:** `Docs/Specs/2026-11-09-opensymbols-design.md` (§5, §6, §7.1, §7.2, §7.5, §10.1, §11).

**Not in P1:** glyph metrics (baseline, cap height, insets), rotation anchor and metric centre. P2 and P4 extend `Drawing` with them when they need them, after `Docs/format/06` states where they are read from.

**This is plan 1 of 5.** P2 runtime (core + react, static icons and the generator's output), P3 demo, P4 animate, P5 Variable Color timing. Each gets its own plan when the previous one is done.

## Global Constraints

- TypeScript end to end; no native code, no WASM, no dependency on or mention of any other project in the repo (spec §1, §13).
- Reference material: private research notes, read-only, not part of this repo. Facts go into `Docs/format/` in its own words.
- No Apple byte in git or in any npm tarball: no catalog, no plist, no CSV, no decoded geometry, no dump output (spec §4, §11).
- Every format constant in code carries a comment citing its `Docs/format/NN-*.md` section (spec §4 "a number with no source").
- The layout is `packages/<name>/src` and `packages/<name>/test`.
- `@opensymbols/decode` has zero runtime dependencies.
- Errors: `class DecodeError extends Error { constructor(readonly where: string, message: string) }`; never return partial results silently.
- Commits: conventional prefix (`decode:`, `cli:`, `docs:`, `build:`), no AI attribution of any kind.
- Catalog root layout: `<root>/public/` = extracted `CoreGlyphs.bundle` contents (`Assets.car` + metadata plists), `<root>/app/` optional (SF Symbols app `Resources/Metadata/` + `colors-26.csv`). `--catalog DIR`, else `$SF_CATALOG_DIR`.
- Reference build `26A5416b`: 8,527 public facets, 31,029 public `BVG ` documents.

## Review Focus

1. A `BVG ` document with type code `0x11` or `0x22` (not just `0x12`): every field after `typeCode` must be read at the document's widths; a parser that hardcodes `u16` still "works" on `0x12` and silently shifts the others. Test pinned in Task 6.
2. A path stream that ends on a half byte (one nibble of padding): must return the commands decoded so far, not throw. Test pinned in Task 5.
3. A facet whose renditions include `Appearance` or `Direction` variants: `master()` must not return the wrong one when both exist. Test pinned in Task 10.
4. A catalog root with no `app/` directory, or an `app/` missing some files: everything still loads, the missing parts are empty. Test pinned in Task 9.
5. An unknown value on a known `-sfsymbols-*` property (a new build's vocabulary): reported as a `DecodeError` naming property and value, never folded into a default. Test pinned in Task 8.
