# P3: Demo Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `opensymbols demo --package DIR` opens a light, local web page that browses a generated package and previews every static knob of every symbol (mode, weight, size, colours, appearance, layout, variable value), with search, categories and copy-to-clipboard.

**Architecture:** The demo is a static Vite + React app (`apps/demo`) built once and shipped inside the `opensymbols` CLI tarball. `opensymbols demo` is a zero-dependency `node:http` server that serves the built app at `/` and the user's generated package at `/pkg/`. The app reads `/pkg/index.json` first and fetches `/pkg/chunks/<n>.json` on demand; it never imports the generated modules, so it renders from data through a new data-driven `<SymbolIcon data>` component in `@opensymbols/react`. A synthetic-package script lets anyone run the demo without a catalog.

**Tech Stack:** Node ≥ 24.2, pnpm workspaces, TypeScript strict ESM, Vite 7, React 19, `@tanstack/react-virtual` (bundled into the demo only), Vitest + happy-dom, Playwright MCP for the visual check (controller step).

**Spec:** `Docs/Specs/2026-11-09-opensymbols-design.md` §2 goal 7, §4 (heavy demo anti-goal, approximations shown), §12.

**Plan 3 of 5.** The Animation panel of the inspector arrives with P4; P3 ships no animation UI and no placeholder for it.

## Global Constraints

- No Apple data in git or tarballs: the demo bundle holds no symbol data; synthetic packages and test output are git-ignored; `pnpm check:pack` stays green with the demo assets inside the CLI tarball.
- No reference to any other project anywhere in the repo.
- `apps/demo` is private (never published); its built `dist/` is copied into `packages/cli/dist/demo/` at CLI build time.
- Every approximation reason a `SymbolIcon` reports is visible in the inspector (spec §4), with the human text from the README's reason table.
- Light (spec §12.2): first paint loads only the app shell and `index.json`; the grid is virtualized; chunks load on demand (at most 4 concurrent fetches, LRU of 24 chunks); the inspector's full-size preview is the only non-cell render.
- Budget (spec §12.2, measured in Task 7): grid visible < 1 s after navigation on a warm local server with a 7,500-symbol synthetic package; scroll at 60 fps on the authors' machine.
- Commits: conventional prefixes (`react:`, `core:`, `cli:`, `demo:`, `build:`, `docs:`), no AI attribution of any kind.
- `opensymbols demo` binds `127.0.0.1` by default; `--host` changes it (e.g. `0.0.0.0` so a browser in WSL can reach it).

## Visual direction

A three-column desktop layout in the spirit of a native symbol browser, built with plain CSS (custom properties, no CSS framework):
- **Sidebar** (220 px): "All" plus categories with counts, from `index.json`.
- **Main**: toolbar (search field, grid/list toggle, cell-size slider 32–96 px, weight and mode quick pickers that apply to the whole grid) above the grid; list view shows icon, name and aliases in rows.
- **Inspector** (320 px): large preview on a checkerboard-free neutral surface, rendering controls, approximation notice, info, copy buttons.
- System font stack, neutral greys, one accent colour; light and dark themes from `prefers-color-scheme` plus a toolbar toggle; focus rings visible; every control keyboard-reachable; arrow keys move the grid selection.
- Narrow windows (< 900 px) collapse the sidebar into a select and stack the inspector under the grid.

## Review Focus

1. A package with zero categories, or symbols with no search terms: sidebar shows only "All", search still matches names. Test in Task 3.
2. Fast scrolling past many chunks: fetches never exceed 4 in flight, out-of-view requests do not block in-view ones, a failed chunk shows an error cell with retry instead of an endless spinner. Test in Task 3.
3. A symbol whose chosen mode is not in its `modes`: inspector shows the "mode" approximation and disables or marks that option. Test in Task 5.
4. `--package` pointing at a directory that is not a generated package, or a port in use: clear CLI error, exit 2. Test in Task 6.
5. Path traversal on the static server (`/pkg/../../secret`): 404, never a file outside the two roots. Test in Task 6.

### Task 1: `<SymbolIcon data>` and portable colours

**Files:**
- Create: `packages/react/src/symbol-icon.tsx`
- Modify: `packages/react/src/create-icon.tsx` (built on `SymbolIcon`), `packages/react/src/index.ts`, `packages/core/src/paint.ts`, `packages/core/src/svg.ts`
- Test: `packages/react/test/symbol-icon.test.tsx`, `packages/core/test/paint.test.ts`, `packages/core/test/svg.test.ts`

**Interfaces:**
- Produces:
  - `SymbolIcon: ForwardRefExoticComponent<IconProps & { data: SymbolData } & RefAttributes<SVGSVGElement>>` (all `IconProps` behaviour of `createIcon`, data passed as a prop; memoised on `data` identity plus props)
  - `createIcon(data)` returns a thin wrapper rendering `<SymbolIcon data={data} …/>` (same public behaviour; existing tests stay green)
  - core: `resolveLayer` never returns an 8-digit hex: a colour `#rrggbbaa` becomes `fill: "#rrggbb"` with its alpha multiplied into `opacity`; `transparent`-like colours (`aa = 00`) make the layer invisible unless it is a knockout.

- [ ] **Step 1: Write the failing tests:** `renderToStaticMarkup(<SymbolIcon data={fixture} weight="bold" />)` equals `renderToStaticMarkup(<Icon weight="bold" />)` for `Icon = createIcon(fixture)`; a named colour `#ff000080` renders `fill="#ff0000"` with `fill-opacity="0.502"`; a `#00000000` named colour on a non-knockout layer omits the path.
- [ ] **Step 2:** Run `pnpm --filter @opensymbols/core test && pnpm --filter @opensymbols/react test` → FAIL. Implement. Run → PASS.
- [ ] **Step 3:** Root `pnpm build && pnpm typecheck && pnpm test`. Commit `react: data-driven SymbolIcon; core: portable colours`.

### Task 2: `index.json` carries what the demo needs

**Files:**
- Modify: `packages/cli/src/generate/index.ts`, `packages/cli/src/generate/write.ts`
- Create: `scripts/synthetic-package.mjs`
- Test: `packages/cli/test/generate/generate.test.ts`, `scripts/synthetic-package.test.mjs`

**Interfaces:**
- Produces in `index.json`:
  - `package: { name: string }` (the generated package's npm name, for import lines)
  - `categories: Array<{ key: string; label: string; icon?: string; count: number }>` (bundle categories joined with app labels; `label` falls back to `key`; `count` = generated symbols in it; order = bundle order)
  - `symbols[].variableValue: boolean` (any layer of the default variant has a `variableThreshold`), `symbols[].approximate: string[]` (reasons fixed at generation: `"palette"` for stand-in multicolor, `"build"` when unvalidated)
- `scripts/synthetic-package.mjs --out DIR --count N [--seed S]`: writes a valid generated package (same layout and `formatVersion` as `generate`, `build.validated: false`, `palette: "stand-in"`) of N geometric symbols (circles, bars, rings; 1–4 layers; some with knockouts, thresholds, dark variants, RTL pairs; categories and search terms) using `@opensymbols/core` types — no catalog, no Apple data. `.gitignore` covers `synthetic*/`.

- [ ] **Step 1: Write the failing tests:** e2e generate output has `package.name`, `categories` with counts, `variableValue` and `approximate` per symbol; `node scripts/synthetic-package.mjs --out <tmp> --count 300` produces a dir whose `index.json` lists 300 symbols across 2 chunks, and whose `symbols/<C>.js` renders through `react-dom/server` without throwing.
- [ ] **Step 2:** Run → FAIL. Implement. Run → PASS.
- [ ] **Step 3:** Commit `cli: index.json for the demo; synthetic packages for development`.

### Task 3: Demo data layer

**Files:**
- Create: `apps/demo/{package.json,tsconfig.json,vite.config.ts,index.html}`, `apps/demo/src/data/{index-model.ts,chunks.ts,search.ts}`
- Modify: `pnpm-workspace.yaml` (add `apps/*`), root vitest config
- Test: `apps/demo/test/data/{chunks.test.ts,search.test.ts,index-model.test.ts}`

**Interfaces:**
- Produces:
  - `type DemoIndex` = the `index.json` shape (Task 2 fields + P2 fields)
  - `loadIndex(base: string, fetchFn?: typeof fetch): Promise<DemoIndex>` (rejects with a readable error on non-200 or a newer `formatVersion`)
  - `class ChunkCache { constructor(base: string, opts?: { maxInFlight?: number /*4*/; capacity?: number /*24*/; fetchFn?: typeof fetch }); get(chunk: number): SymbolData[] | undefined; load(chunk: number, priority: number): Promise<SymbolData[]>; retry(chunk: number): void; subscribe(fn: () => void): () => void; error(chunk: number): Error | undefined }` (dedupes in-flight loads; higher priority first; evicts least-recently-used; never more than `maxInFlight` concurrent)
  - `search(index: DemoIndex, query: string, category?: string): number[]` (indices into `index.symbols`; empty query → all in index order; ranking: exact name > name prefix > name token prefix > alias > search term; ties keep index order; case-insensitive)

- [ ] **Step 1: Write the failing tests:** search ranks `wifi` before `wifi.slash` before `antenna` (alias `wifi`) for query "wifi"; category filter; empty categories (**Review Focus 1**); ChunkCache with a fake fetch: 10 loads → never more than 4 in flight; a failed chunk exposes `error()` and `retry()` refetches; capacity 2 evicts the LRU chunk (**Review Focus 2**).
- [ ] **Step 2:** Run `pnpm --filter demo test` → FAIL. Implement. Run → PASS.
- [ ] **Step 3:** Commit `demo: data layer (index, chunks, search)`.
